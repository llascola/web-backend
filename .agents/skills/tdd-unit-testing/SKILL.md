# TDD: Unit Testing (The Base)

The foundation of the project's Test Pyramid ensures that core business logic (`domain` and `services`) executes perfectly without ever touching a disk, database, or network.

## 1. Domain Testing (Table-Driven)

The `internal/app/domain` layer has exactly zero external dependencies.

**Strategy**: Use exhaustive **Table-Driven Tests** with standard `testing` and `testify/assert`.

### Example
```go
func TestUserRole(t *testing.T) {
	tests := []struct {
		name     string
		role     domain.UserRole
		expected bool
	}{
		{"Valid Admin", domain.RoleAdmin, true},
		{"Valid Member", domain.RoleMember, true},
		{"Invalid Role", "superadmin", false},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			isValid := domain.IsValidRole(tt.role)
			assert.Equal(t, tt.expected, isValid)
		})
	}
}
```

## 2. Service Layer Testing (Mock-Driven)

The `internal/app/services` layer coordinates the domain and interacts via **Out-Ports** (interfaces). We NEVER test the service layer with a real database.

**Strategy**: Generate mocks for Out-Ports (`mockery`) and inject them (`testify/mock`).

### Step 1: Regenerate Mocks
If you modified any interfaces in `internal/app/outports/`, regenerate mocks:
```bash
make mocks
```

### Step 2: Inject and Expect
Use `testify/mock` to assert that the service interacts correctly.

```go
func TestServiceFunction(t *testing.T) {
	// 1. Instantiate the Mocks generated by Mockery 
	// (Ensure you use the exact generated constructor name, e.g. NewMockUserRepository)
	mockRepo := mocks.NewMockUserRepository(t)
	mockTokenGen := mocks.NewMockTokenGenerator(t)

	// 2. Inject the mocks into the service
	service := services.NewAuthService(mockRepo, mockTokenGen, nil)

	// 3. Define the Expectations
	mockRepo.On("FindByID", mock.Anything, expectedUser.ID).Return(expectedUser, nil)

	// 4. Execute the Logic
	result, err := service.DoSomething(context.Background(), expectedUser.ID)

	// 5. Assert the Results
	require.NoError(t, err)
	assert.NotNil(t, result)
	
	// 6. Assert Expectations Met (Very Important!)
	mockRepo.AssertExpectations(t)
}
```

### Mocking Rules
- **Return Values**: Use `.Return(value, err)` to simulate DB responses/errors.
- **Dynamic Assertions**: Use `.Run(func(args mock.Arguments) {...})` to verify dynamically created fields on objects passed into mocks (e.g. asserting a new user ID was appended to the object before saving).
